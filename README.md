# OpenCode Mobile (изолированный MVP)

Мобильное PWA для доступа к серверу **OpenCode** (отдельный продукт, не входит в
состав репозитория «Учёт самосвалов»). Изолированный каталог, не влияет на
production/test приложение.

Возможности:

- Подключение к серверу OpenCode по IP-адресу и порту, логину и паролю через HTTPS и HTTP Basic.
- Форма подключения, состояние соединения, выход, новая сессия.
- Мобильный чат: список и создание сессий, отправка и периодический REST-опрос
  сообщений, остановка генерации, вывод ошибок. Это MVP, не полная реализация
  возможностей OpenCode.
- Голосовой ввод через **Web Speech API** (`webkitSpeechRecognition`) с большой
  кнопкой микрофона и редактированием распознанного текста перед отправкой.
- Озвучивание ответов через **браузерный `speechSynthesis`**: прочитать,
  пауза/возобновление, стоп,
  регулировка скорости, выбор языка/голоса, очистка Markdown, код по
  умолчанию не читается.
- PWA: mock-режим для разработки, тёмная тема, адаптация под 393×852,
  service worker, офлайн-загрузка собранных статических файлов.

## Быстрый старт

Каталог полностью статический — сборка не требуется.

Локально (develop, mock):

```bash
cd opencode-mobile
python3 -m http.server 8321
# откройте http://localhost:8321/ в Chrome/Chromium
```

В форме подключения выберите режим **Mock** — приложение работает без сервера
OpenCode, отвечает встроенный имитатор.

Для работы с реальным сервером OpenCode выберите режим **OpenCode** и
укажите адрес (см. ниже).

### Запуск тестов

```bash
cd opencode-mobile
node --test tests/*.test.mjs
```

## Режимы работы

| Режим | Что делает |
|---|---|
| `mock` (по умолчанию) | Локальная имитация сервера: создание сессии, потоковые ответы, остановка. Полезно для разработки UI, голоса и PWA без сети. |
| `opencode` | Подключение к реальному серверу по REST API v2 с HTTP Basic. Сессии и сообщения обновляются REST-опросом; WebSocket не используется. Контракт описан в [`CONTRACT.md`](CONTRACT.md). |

## Настройка IP / порта / логина / пароля

В форме подключения:

- **Хост** — IP-адрес или имя сервера OpenCode (например `192.168.1.50`).
- **Порт** — порт API-сервера OpenCode.
- **Логин** — имя пользователя OpenCode.
- **Пароль** — поле с маскировкой; не включается в URL. Хранение параметров
  подключения зависит от режима и реализации клиента.
- **Режим** — `OpenCode` или `Mock`.

Basic-заголовок и пароль **не** сохраняются в хранилище браузера: пароль
используется только в памяти клиента и очищается при отключении/выходе.
Если интерфейс запоминает параметры подключения, пароль в них не входит.

## Голосовой ввод и озвучивание

### Голосовой ввод

- Большая кнопка микрофона рядом с полем ввода.
- Распознавание через `webkitSpeechRecognition` (Web Speech API); язык
  задаётся приложением (`ru-RU`), отдельной настройки в UI нет.
- Распознанный текст попадает в текстовое поле — его **можно отредактировать
  перед отправкой**.
- Во время записи кнопка меняет состояние; повторное нажатие завершает запись.
  Поведение при тишине зависит от браузера и платформы.

### Озвучивание ответов (системный TTS)

Используется браузерный `speechSynthesis`; доступность и состав голосов зависят
от браузера и платформы. Внешние TTS-сервисы приложением не подключаются.

Панель озвучивания ответа:

- **Прочитать** — озвучить последний ответ ассистента.
- **Пауза** / **Возобновить** — `speechSynthesis.pause()` / `resume()`.
- **Стоп** — `speechSynthesis.cancel()`.
- **Скорость** — ползунок от 0.5× до 2.0× (по умолчанию 1.0).
- **Язык** — `Авто` / `Русский` / `Английский`. В режиме «Авто» язык ответа
  определяется по тексту (наличие кириллицы), при выборе явного языка —
  используется он.
- **Читать код** — выключено по умолчанию: блоки кода и inline-код пропускаются
  (заменяются коротким «код»). Если включить — код произносится буквально
  (на практике читается плохо, поэтому по умолчанию выключено).
- Кнопка **«Список голосов»** — показывает голоса, доступные через
  `speechSynthesis.getVoices()`. Интерфейс не помечает выбранный голос.

Выбор голоса: при автоопределении ищется голос с самым близким языком к языку
ответа (точное совпадение `ru` → `ru-*` → похожий язык → системный голос по
умолчанию). Логика выбора вынесена в чистую функцию и покрыта тестами.

## Публикация на GitHub Pages

Приложение — статическая клиентская часть без backend-прокси. Пути рассчитаны
на обслуживание из каталога приложения. Ветка `OpencodePWA` — исходная ветка,
а не автоматически созданный отдельный сайт GitHub Pages. Не загружайте каталог
поверх сайта «Учёт самосвалов»: сначала отдельно согласуйте и настройте изоляцию
сайта и канал публикации.

### Статус публикации

Публикация этим изменением не настраивалась и не выполнялась. Нельзя считать
ветку `OpencodePWA` отдельным Pages-сайтом или предлагать публиковать только
`opencode-mobile/` в уже используемый Pages-канал без явного согласования.

По состоянию на эту проверку Pages использует legacy source root `/` по адресу
https://iluxaspb.github.io/Samosval/. `OpencodePWA` не опубликована; настройки
Pages не переключались.

Проверка из текущего окружения: `GET
https://iluxa.synology.me:4097/api/info` ответил `401` с Basic challenge;
`OPTIONS` ответил `204`, но без `Access-Control-Allow-Origin` для Origin
`https://iluxaspb.github.io`, поэтому браузерный доступ с этого origin
блокируется CORS. Проверка TLS-цепочки на `443` завершилась ошибкой в текущем
окружении; это не глобальный вывод о сертификате.

### ВАЖНО: ограничение mixed content

Клиент поддерживает HTTP(S) base URL; при обслуживании страницы по HTTPS браузер
блокирует запросы к `http://IP:PORT` как mixed content. Для подтверждённого
NAS-подключения используйте настроенные HTTPS и порт.

Чтобы работать с реальным сервером с GitHub Pages, серверу OpenCode нужен один
из вариантов:

- **HTTPS** с валидным для браузера сертификатом и открытым портом;
- сервер, доступный по https-домену с **разрешённым CORS** (заголовки
  `Access-Control-Allow-Origin` для вашего Pages-домена) и доступный с телефона.

Без этого используйте локальный запуск (`npm`-сервер свои, `python3 -m
http.server` и т.п. — но и там голосовой ввод требует localhost/HTTPS, см.
ниже). Работа в браузере телефона по HTTP в локальной сети здесь не проверялась.

CORS: если сервер OpenCode требует `Origin` — настройте его разрешать домен
Pages. Наш клиент не может обойти CORS (это ограничение браузера, а не сервера).

## Ограничения браузерных голосовых API

- **Распознавание речи (Web Speech API, микрофон)** зависит от поддержки браузера,
  разрешения микрофона и платформенного сервиса. Оно может требовать сеть или
  внешний системный сервис; гарантии офлайн-работы и приватности обработки нет.
  Автоматические тесты браузера через Playwright могут не покрывать реальное
  распознавание (зависит от микрофона и прав).
- **`speechSynthesis`** в браузере обычно требует
  пользовательского жеста (первый клик) для запуска; список голосов может
  подгружаться асинхронно (`voiceschanged`) — приложение слушает это событие.
  Наличие браузерных голосов и их соответствие установленным на устройстве
  движкам не гарантировано. Не все голоса умеют паузу; если голос не поддерживает паузу —
  пауза заменяется остановкой.
- Пока идёт озвучивание, повторное «Прочитать» сбрасывает и начинает заново.
- Отключённый микрофон/отказ в разрешении показывается тостом.

## Совместимость с сервером OpenCode

- Используется REST API v2 сервера OpenCode; детали вызовов — в
  [`CONTRACT.md`](CONTRACT.md). Сообщения обновляются опросом, это не потоковый
  транспорт и не полная функциональная совместимость.
- MVP не предоставляет браузерный интерфейс просмотра/редактирования файлов,
  просмотра diff, выбора терминала, выбора модели или управления permissions.
- Возможности сервера, не перечисленные в этом MVP, не обещаются клиентом.

## Разработка и тесты

Тесты без зависимостей (Node 22+):

```bash
node --test tests/*.test.mjs
```

Покрытие: парсер событий WebSocket, URL-сборка, выбор голоса TTS, очистка
Markdown, mock-транспорт (поток, остановка, ошибка), извлечение «danger»-текста.

## Безопасность

- Пароль и Basic-заголовок не записываются в localStorage/sessionStorage и не
  добавляются в URL; пароль используется только в памяти клиента.
- Приложение не подключает внешний TTS-сервис; браузерные голосовые API могут
  использовать платформенные службы, их реализация приложению неподконтрольна.
- Реальные секреты (токены GitHub, ключи) в репозиторий не встраиваются.

## Журнал MVP

- MVP: подключение REST API v2 с Basic auth в памяти, список/создание сессий,
  REST-опрос сообщений, mock-режим и браузерные голосовые функции. Номер версии
  не назначен.
