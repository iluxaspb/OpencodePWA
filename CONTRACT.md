# Контракт OpenCode Mobile MVP

## Подключение

На момент проверки legacy GitHub Pages source root — `/`, адрес
https://iluxaspb.github.io/Samosval/. `OpencodePWA` не опубликована; Pages
настройки не менялись. Доступ к NAS API из текущего окружения: `GET
https://iluxa.synology.me:4097/api/info` вернул `401` с Basic challenge,
`OPTIONS` — `204` без `Access-Control-Allow-Origin` для Origin
`https://iluxaspb.github.io` (браузерный запрос с этого origin блокируется
CORS). Проверка TLS-цепочки на `443` завершилась ошибкой только в текущем
окружении, это не глобальная оценка сертификата.

Клиент `js/core/v2-client.js` обращается к HTTP API v2. Базовый URL строится из
выбранной схемы, IP/имени хоста и порта, например `https://192.168.1.50:10999`.
Для NAS подтверждены адрес/порт, HTTPS и HTTP Basic. Сертификат должен быть
приемлем браузеру; браузерная политика CORS также должна разрешать запросы.

Имя пользователя и пароль преобразуются в заголовок `Authorization: Basic …`.
Заголовок хранится только в памяти экземпляра клиента, не в storage и не в URL.
При `disconnect()` он очищается, выполняющиеся запросы отменяются. Пароль из
поля формы очищается после создания клиента.

## Используемые REST-вызовы

Клиент выполняет следующие вызовы; тела и ответы обрабатываются как JSON:

| Назначение | Метод и путь |
|---|---|
| Информация о сервере | `GET /api/info` |
| Список сессий | `GET /api/session` |
| Создание сессии | `POST /api/session`, тело `{}` |
| Список сообщений сессии | `GET /api/session/{id}/message` |
| Отправка prompt | `POST /api/session/{id}/prompt`, тело `{ "text": string }` |
| Прерывание генерации | `POST /api/session/{id}/interrupt` |

Идентификатор сессии кодируется как URL-компонент. Ошибка HTTP-статуса выше
успешного диапазона приводит к ошибке клиента. Ответ `204` считается пустым.
Для ожидания ответов приложение повторно запрашивает список сообщений примерно
каждые 1,8 секунды. Постоянного WebSocket/SSE-соединения и потоковой доставки
ответа нет.

## Границы MVP

Поддерживаются базовые операции сессиями и текстовыми сообщениями, доступные в
реализованном клиенте. Это не полная функциональная паритетность с OpenCode.
В интерфейсе MVP отсутствуют просмотр и редактирование файлов, просмотр diff,
выбор терминала, выбор модели и UI управления permissions. Клиент не заявляет
поддержку других функций сервера, которых нет в интерфейсе и API-адаптере.

## Mock

Режим `mock` использует `js/core/mock-transport.js` для локальной разработки и
не является контрактом реального сервера. Реальный режим использует только
`v2-client.js`; прежние схемы `/me` и WebSocket-событий не применяются.
